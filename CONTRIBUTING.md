# CONTRIBUTING — как мы работаем с git

## Ветки

- `main` — стабильная ветка. Прямой push запрещён. Только через PR.
- `dev/codec` — долгоживущая ветка разработчика алгоритма (`codec/`).
- `dev/api` — долгоживущая ветка разработчика ПО (`api/`, `web/`).
- `dev/devops` — долгоживущая ветка DevOps (`deploy/`, `.github/`).
- `dev/qa` — долгоживущая ветка QA (`tests/`).

Каждый работает только в своей ветке. Не коммить в чужие ветки и в main.

## Дисциплина синхронизации с main (обязательно)

Долгоживущая ветка быстро расходится с main — это нормально, но только если
её регулярно синхронизировать.

Минимум раз в 1–2 дня, а также перед началом новой задачи:

```bash
git checkout dev/<своя-роль>
git fetch origin
git merge origin/main
```

Конфликты решаются в своей ветке, не в main.

## Как делать задачу

1. Синхронизироваться с main (см. выше).
2. Работать в своей ветке `dev/<роль>`, коммитить маленькими шагами.
3. Перед PR прогнать локально:
   ```bash
   make lint
   make test
   ```
4. Запушить свою ветку:
   ```bash
   git push origin dev/<своя-роль>
   ```
5. Открыть PR из `dev/<роль>` в `main`.
   В описании PR: что сделано, какие контракты затронуты, как проверял.
6. Дождаться ревью минимум от одного человека из другой роли.
7. После мержа в main — синхронизировать свою ветку с main снова.

## Контракты и общие файлы

Эти файлы нельзя менять в одиночку — только через отдельный PR с ревью
всех затронутых ролей:

- `codec/__init__.py` — сигнатуры encode/decode
- `codec/errors.py` — классы ошибок
- `openapi.yaml` — HTTP API
- `AGENTS.md` — правила проекта
- `CONTRIBUTING.md` — этот файл

Пометка в PR: `contract: <что меняется>`.

## Сообщения коммитов

`type: short description`

Типы: feat, fix, docs, test, chore, refactor, perf.

Примеры:
- `feat: add binary rate control`
- `fix: handle 1x1 png in encoder`
- `docs: describe format header`
- `test: add check scenario for 512x512`

## Чего НЕ делать

- Не пушить в main.
- Не коммитить в чужие ветки.
- Не менять контракты без отдельного PR и ревью.
- Не смешивать в одной ветке изменения из разных зон
  (например, `codec/` и `api/` одновременно).
